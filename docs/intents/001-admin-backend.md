# 意圖 001：後台管理系統

## 為什麼要做
現在要改作品資料、換照片，都得改 JSON 或把檔案放進資料夾，再 git push 部署。
這件事只有會寫程式的人做得到。目標是讓**老師登入網頁就能管理展覽內容**。

## 要做到什麼
1. 管理員登入／登出（帳號由指令建立，不開放註冊）。
2. 作品：新增、修改、刪除、上架／下架、調整順序；可上傳圖片與語音導覽。
3. 分區：新增、改名、調整順序；分區內還有作品時不可刪除。
4. 藝術小尖兵：新增、修改、刪除、調整順序；可上傳頭像。
5. 相簿（美術館參訪、導覽培訓、展覽現場、開幕典禮、展覽與教學）：多張上傳、刪除、調整順序。

## 不能改變的事
- 前台所有頁面的外觀與內容，在匯入現有資料後必須和現在完全一樣。
- 網址不變，尤其是展場 QR Code 用的 `/artworks.html?art=<作品編號>`，所以作品編號（如 `C-03`）要可編輯但不可重複。
- 下架的作品不出現在前台，用 QR Code 開也打不開。

## 技術決定
| 項目 | 選擇 | 理由 |
|---|---|---|
| ORM | Flask-SQLAlchemy | 同一份程式碼可在本機用 SQLite、上線用 PostgreSQL |
| 資料表版本 | Flask-Migrate (Alembic) | 之後加欄位不用砍資料庫 |
| 登入 | Flask-Login + Werkzeug 密碼雜湊 | 標準做法，不自己發明 |
| 表單 | Flask-WTF | 內建 CSRF 防護與檔案驗證 |
| 上傳檔名 | 隨機 UUID | 避免中文檔名問題、檔名衝突、路徑穿越 |

## 安全檢查清單
- [x] 所有 `/admin/*` 都需要登入（登入頁除外）
- [x] 所有寫入動作都是 POST 且有 CSRF token
- [x] 上傳只允許指定副檔名，並限制檔案大小
- [x] 登入後的 `next` 轉址只允許站內路徑（避免 open redirect）
- [x] SECRET_KEY 不寫死在程式碼中
- [x] 刪除資料時只刪除後台上傳的檔案，不動 git 裡的原始素材

## 已知限制（之後再處理）
- Render 免費方案的硬碟會在重新部署時清空：上線前，上傳檔案要改存雲端儲存或掛載持久硬碟。
- 沒有登入失敗次數限制。
